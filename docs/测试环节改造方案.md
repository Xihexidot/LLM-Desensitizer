## 一、现有测试体系运作机制梳理

### 1.1 技术栈与规模

| 维度 | 现状 |
|---|---|
| 后端测试框架 | JUnit 5 + Spring Boot Test + Mockito + AssertJ |
| 构建/调度 | Maven Surefire（单模块），`mvn test` / `mvn verify` 两级阶段 |
| 测试类 / 用例数 | 18 个测试类 / **93 个测试用例** |
| 前端/插件测试 | Playwright（Chromium + Edge）+ Node 内置测试（managed-store 单测） |
| 数据源 | `my_pii_test_set.json`（1255 条 PII 实体）+ `security_attack_test_set.json`（12 条攻防用例） |

### 1.2 自动化测试执行流程

```
提交代码 → [可选 CI] mvn test → mvn verify → mvn verify -Psecurity-scan → 上传报告
                                   │              │
                                   ├─ SpotBugs 静态扫描（不阻断构建）
                                   ├─ JaCoCo 覆盖率（target/site/jacoco）
                                   └─ 插件 job：npm run test:unit + playwright chromium/msedge
```

### 1.3 用例调度规则

- **后端**：Surefire 自动发现 `*Test.java`；`@SpringBootTest` 类共享应用上下文（容器复用）；`NlpScannerTest` 等对 Ollama/外部 LLM 采用 Mock/降级，保证本地与 CI 无外部依赖即可运行。
- **插件**：Playwright `testDir: tests`，`workers: 1` 串行执行（避免 MV3 扩展多实例状态污染）；mock-server 由 `webServer` 钩子自动拉起（端口 8899），测试结束自动回收。
- **安全专项**：攻防/合规/动态漏洞测试独立成包 `com.hdu.apisensitivities.security`，与业务单测隔离，可按 `-Dtest=Security*Test` 定向执行。

### 1.4 环境部署方式

- **本地**：`.env` 注入环境变量，`pom.xml` 将 `.env` 复制进 classpath；测试依赖 H2 内存库 + HanLP 离线模型，零外部服务即可全量运行。
- **CI**：`ubuntu-latest`（后端）+ `windows-latest`（插件，预装 Microsoft Edge，验证主流浏览器适配）；GitHub Actions 双 job 并行。

### 1.5 结果反馈链路

```
测试执行 → surefire/playwright 报告 → CI Artifact 归档（30 天）
          ├─ target/surefire-reports/        后端用例级结果
          ├─ target/site/jacoco/             覆盖率
          ├─ target/spotbugsXml.xml          静态扫描缺陷
          ├─ target/dependency-check-report.html  供应链漏洞
          └─ plugin/playwright-report/       插件 E2E 截图/视频/跟踪
```

### 1.6 原测试工具链对浏览器插件的支持情况（改造前排查结论）

- **盲区 1**：原体系仅有后端 JVM 测试，**无任何浏览器插件测试链路**——content script 注入、popup 交互、MV3 Service Worker 生命周期、chrome.storage.managed 策略加载等关键逻辑零验证。
- **盲区 2**：原体系**无 CI**，`mvn test` 仅本地手动执行，无回归看门狗。
- **盲区 3**：无静态代码安全扫描、无供应链漏洞检测、无覆盖率强制门禁。
- **盲区 4**：测试数据集中于"正常 PII 输入"，无攻防/越权/注入/绕过检测类高价值场景。
- **盲区 5**：无审计加密、无合规性（等保/数据安全法）专项校验用例。

## 二、测试集数据源构成与覆盖缺口评估

### 2.1 数据源构成

| 数据源 | 规模 | 生成逻辑 | 覆盖范围 |
|---|---|---|---|
| `my_pii_test_set.json` | 1255 条实体 | 程序化生成（边界值、随机组合、中文名/地址/机构等 NLP 语料） | 8 类 PII：手机号/身份证/银行卡/邮箱/姓名/地址/机构/密码等，覆盖中英文、空格/连字符变体、会话一致性 |
| `security_attack_test_set.json` | 12 条攻防用例 | 从真实攻防案例与 OWASP Top 10 / OWASP LLM Top 10 提炼 | 5 类场景：DATA_LEAK 数据泄露 / INJECTION 注入攻击 / ACCESS_CONTROL 越权访问 / XSS 跨站脚本 / OBFUSCATION 绕过检测 |

### 2.2 场景还原度与覆盖缺口（改造前评估）

| 缺口类别 | 具体缺口 | 改造对策 |
|---|---|---|
| 边界场景 | 长文本超限、空/纯符号输入、超长连续数字 | 动态漏洞测试新增畸形输入/超长文本（5 用例） |
| 异常场景 | 非法 JSON、NUL 字节、外部 LLM 不可用 | 动态漏洞测试覆盖 + NlpScanner 降级路径 Mock |
| 数据泄露 | 日志/配置文件整段泄露、云凭证、JWT、DB 连接串 | 攻防集 6 条 LEAK 用例 + 片段级残留断言 |
| 越权访问 | IDOR 横向/纵向越权、权限提升 | 攻防集 2 条 ACCESS 用例 |
| 注入攻击 | SQL 注入、提示注入（LLM 越权指令） | 攻防集 2 条 INJECTION 用例 + 防过度脱敏断言 |
| XSS | 脚本载荷携带 PII 外传 | 攻防集 XSS-001 |
| 绕过检测 | 空格/连字符/Unicode 变体规避正则 | 攻防集 OBFUSCATION-001 + 正则边界 `(?<!\d)` 加固 |
| 合规场景 | 审计存储明文、加密往返/篡改 | SecurityComplianceTest 3 用例 + ContentCipher 审计加密 |
| 浏览器端 | 插件功能/兼容/安全零覆盖 | Playwright 双浏览器 E2E 5+5 用例 + managed-store 单测 6 用例 |

### 2.3 攻防集实测发现（数据价值的直接证明）

- 修正非法身份证校验位用例（LEAK-006 由 `...234` 修为合法号码 `...231`），验证系统 MOD 11-2 校验严苛性；
- 发现并修复 INJECTION-002 密码 `Admin@2026!` 被 NLP 误判 ORGANIZATION 吞并导致部分明文残留的**真实缺陷**（DesensitizationManager 新增凭据类型优先合并规则）；
- 发现并修复 ContentCipher `SecureRandom` 每次新建的安全编码问题（SpotBugs High 级）。

## 三、专项改造内容（已落地）

### 3.1 浏览器插件全流程自动化测试验证环境

**交付物**（`plugin/` 目录）：

| 文件 | 职责 |
|---|---|
| `playwright.config.js` | 双项目（chromium / msedge），`workers: 1`，webServer 自动拉起 mock-server |
| `tests/mock-server.js` | 网关契约模拟（`/plugin/audit-check`、`/plugin/confirm-action`、`/audit/requests`、`/audit/reset`），内置宽松正则 |
| `tests/mock-ai-page.html` | 模拟 AI 对话页（`#prompt` / `#send` / `#sent`） |
| `tests/extension.spec.js` | 5 个 E2E 用例：扩展加载 / 功能全流程 / 无敏感放行 / 高风险拦截 / XSS 防执行 |
| `tests/managed-store.unit.js` | managed-store（chrome.storage.managed 企业策略三级降级链）6 个单测 |
| `manifest.json` | content_scripts 新增 `http://127.0.0.1:*/*`、`http://localhost:*/*` 白名单 |

**验证结果**：Chromium 5/5 ✅、Edge 5/5 ✅、managed-store 6/6 ✅（功能 + 兼容 + 安全三向覆盖，Edge 验证主流浏览器版本适配）。

### 3.2 攻防场景测试集重构扩充

- 新增 `src/test/resources/security_attack_test_set.json`（12 条用例，5 类场景），每类均标注 `source`（真实攻防案例来源）以支撑可追溯性。
- 新增 `high_mask_secrets` 字段：对 PASSWORD/API_KEY/ID_CARD 等高敏类型，断言其**任意 ≥4 字符连续字母数字片段**均不得残留，杜绝"Admin@"式部分泄露（`SecurityAttackScenarioTest.extractRuns` + 正则 `[A-Za-z0-9]{4,}`）。
- 新增 `preserve` 字段：注入载荷结构（如 `' OR '1'='1' --`）必须保留，防过度脱敏。

### 3.3 自动化测试体系升级

| 专项环节 | 落地方式 | 产物 | 状态 |
|---|---|---|---|
| 静态代码安全扫描 | SpotBugs 4.8.6.6（effort=Max，threshold=Medium，failOnError=false） | `target/spotbugsXml.xml` | ✅ 已发现并修复 High 级问题 |
| 代码覆盖率 | JaCoCo 0.8.13（verify 阶段） | `target/site/jacoco/` | ✅ |
| 供应链漏洞检测 | OWASP dependency-check（`-Psecurity-scan`，HTML 报告，failBuildOnCVSS=11 防误伤） | `target/dependency-check-report.html` | ✅ CI 以 continue-on-error 运行 |
| 动态漏洞检测 | `DynamicVulnerabilityTest`（MockMvc 黑盒攻击载荷：SQL 注入 / 提示注入 / XSS / 畸形输入 / 超长文本） | 5 用例 | ✅ 全通过 |
| 合规性校验 | `SecurityComplianceTest`（审计加密回读 / legacy 明文兼容 / ContentCipher 往返·篡改·边界） | 3 用例 | ✅ 全通过 |
| 攻防场景回归 | `SecurityAttackScenarioTest`（12 条攻防用例 × 3 项断言） | 1 用例（数据驱动） | ✅ 全通过 |
| 可追溯 / 可复盘 | GitHub Actions CI 双 job + Artifact 归档（surefire / jacoco / spotbugs / dependency-check / playwright 报告，保留 30 天） | CI 产物 | ✅ |
