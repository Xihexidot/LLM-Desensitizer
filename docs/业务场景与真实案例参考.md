## 三、受监管行业场景

### 3.1 金融

客户经理用 AI 起草客户分析 → 输入含客户姓名、身份证、资产信息，需满足 **PCI-DSS / 反洗钱** 审计要求。

### 3.2 医疗

医生用 AI 整理病例摘要 → 输入含患者姓名、诊断结果，需满足 **HIPAA** PHI 数据不出境的要求。

### 3.3 律所

律师用 AI 总结证据材料 → 含当事人隐私和特权信息，一旦泄露后果严重。

### 3.4 政府

公务员用 AI 起草政策文件 → 含内部数据，[CISA 局长案例](https://blog.rockfort.ai/post/cisa-chatgpt-data-leak-how-america-s-top-cybersecurity-official-exposed-the-1-enterprise-ai-risk) 是最直接的教训。

## 四、科技/研发企业

- **源代码泄露**：开发者把代码贴进 Copilot/ChatGPT 调试
- **商业机密推断**：即使输入碎片化信息，AI 可通过关联分析还原完整情报
- **影子 AI**：[Verizon 报告](https://blog.csdn.net/PigWriter/article/details/152931948) 70% 员工会用个人邮箱、热点绕过企业管控

---

## 五、为什么是"监控 + 脱敏"而不是"禁用"

1. **禁用产生影子 AI**：DHS 做了内部版 DHSChat，[局长仍选公共版 ChatGPT](https://blog.rockfort.ai/post/cisa-chatgpt-data-leak-how-america-s-top-cybersecurity-official-exposed-the-1-enterprise-ai-risk)
2. **全面禁用的代价**：三星禁用后又部分放开，竞争对手在用 AI 提升效率
3. **行业共识**：[Browser DLP 市场 2026 对比](https://anonym.legal/blog/blocking-vs-anonymization-browser-dlp-2026) 已验证两种路线：阻断 (Nightfall) vs 脱敏后放行 (anonym.legal)

## 六、对应到本项目的定位

```
员工用 AI → 浏览器插件自动检测敏感信息
  → 弹窗展示命中类型 + 脱敏预览
  → 可选"发送脱敏版 / 取消"
  → 每条操作写入审计表
  → 管理员 Dashboard 即时可见
```

与 [市场中已有产品](https://www.teramind.co/blog/enterprise-ai-data-loss-prevention-tools/)（Teramind、Nightfall、Strac、Microsoft Purview Browser DLP）的路线一致：**浏览器端点检测 + 策略引擎 + 审计合规**。

## 七、答辩用法（一句话版）

> "三星 20 天内 3 次源代码泄露，CISA 局长都栽在 ChatGPT 上 — 人性不改，工具要补。我们做的是浏览器端检测→脱敏→放行→审计闭环，不改变员工习惯，不过度干预效率，但保证每一条记录可追溯。"
