### 1.2 当前 3 个断点

| 断点 | 现状 | 影响 |
|------|------|------|
| **审计无 DB 持久化** | 审计事件存 `CopyOnWriteArrayList`，服务重启即丢失；TTL 7 天自动清理 | 管理员查不到历史审计记录 |

| **插件不走审计管道** | `background.js` 调 `/desensitize/text`（纯检测，不写审计） | 员工在 DeepSeek 输入敏感信息 → 弹窗 → 后端完全不知道谁选了什么 |

### 阶段 C：插件审计接入（1h）

#### C1. 新增 `PluginAuditController`

```java
@RestController
@RequestMapping("/plugin")
public class PluginAuditController {
    
    // ① 检测 + 写入审计记录
    @PostMapping("/audit-check")
    public ResponseEntity<PluginCheckResponse> auditCheck(@RequestBody PluginCheckRequest req) {
        // 调用 DesensitizationManager 做检测
        DesensitizationResponse result = desensitizationManager.process(req.toDesensitizationRequest());
        
        // 立即写入审计（userAction = null 表示"待用户确认"）
        GatewayAuditEvent event = buildAuditEvent(req, result);
        auditRepository.save(event);
        
        return ResponseEntity.ok(PluginCheckResponse.builder()
            .detectedEntities(result.getDetectedEntities())
            .desensitizedContent(result.getDesensitizedContent())
            .auditEventId(event.getEventId())
            .build());
    }
    
    // ② 用户确认后回调
    @PostMapping("/confirm-action")
    public ResponseEntity<Void> confirmAction(@RequestBody ConfirmActionRequest req) {
        auditRepository.updateUserAction(req.getAuditEventId(), req.getUserAction());
        return ResponseEntity.ok().build();
    }
}
```

`PluginCheckRequest` 字段：

```java
@Data
public class PluginCheckRequest {
    private String content;
    private String dataType;
    private String userId;       // ← 需要插件传过来
    private String department;   // ← 需要插件传过来
    private String channel;      // 固定 "BROWSER_PLUGIN"
}
```

## 5. 实施后效果

### 5.1 插件的完整审计链路

```
员工在 DeepSeek 粘贴 "客户张三 13812345678"
  → 点击发送
  → 插件截获 → POST /plugin/audit-check
    { content, userId: "zhangsan", department: "客服部" }
  → 后端检测 → 命中 PHONE + PERSON
  → 写入 audit 表: { eventId: "evt-001", userId: "zhangsan", userAction: null }
  → 返回 { detectedEntities, desensitizedContent, auditEventId: "evt-001" }
  → popup.js 弹窗
  → 用户选 "取消"
  → POST /plugin/confirm-action { auditEventId: "evt-001", userAction: "CANCEL" }
  → 后端 UPDATE audit SET user_action='CANCEL' WHERE event_id='evt-001'

管理员 Dashboard 实时看到：张三（客服部）在 DeepSeek 输入含手机号+姓名的文本，用户选择了取消。
```
