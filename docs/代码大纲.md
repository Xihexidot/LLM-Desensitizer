# 代码大纲

## 1. 项目概览

本项目是一个 **LLM 输入输出脱敏与识别** 系统，技术栈为 **Spring Boot 3 + MyBatis + H2/MySQL + Vue 3 + Vite**。

系统由 **5 个子系统** 构成，按职责分为：

| 子系统 | 目录 | 职责 |
|--------|------|------|
| **后端核心** | `src/` | 敏感检测、脱敏、LLM 代理、企业网关、规则管理 |
| **前端管理台** | `front_end/` | 脱敏操作、审计查看、规则管理、策略配置、可视化 |
| **浏览器插件** | `plugin/` | AI 网站输入拦截、检测弹窗、用户确认回调 |
| **Python 脚本** | 根目录 `.py` | 测试数据生成、数据集导入 |
| **测试集** | `src/test/` | 单元测试、基准测试、集成测试 |

### 1.1 核心数据流

```
用户输入 → [前端/插件/API] → Controller → DesensitizationManager
                                              │
                          ┌───────────────────┼───────────────────┐
                          ▼                   ▼                   ▼
                   DataParserManager   SensitiveDetection   DesensitizationStrategy
                   (格式解析)          (正则+NLP+自定义)    (掩盖/泛化/占位符)
                                              │
                                              ▼
                                    脱敏后内容 → LLM 调用 → 占位符恢复 → 返回结果
```

### 3.3 领域模型 `entity/`

#### 敏感信息模型

**[SensitiveType](file:///e:/Java/Llm输入输出脱敏与识别/src/main/java/com/hdu/apisensitivities/entity/SensitiveType.java)** — 敏感类型枚举(17种)：

| 类别 | 枚举值 | 检测方式 | 严重级别 |
|------|--------|----------|---------|
| 个人标识 | PHONE_NUMBER, EMAIL, ID_CARD, NAME | 正则 | 高 |
| 金融信息 | BANK_CARD, CREDIT_CARD | 正则 | 高 |
| 证件号 | PASSPORT, SOCIAL_SECURITY, BIRTH_DATE | 正则 | 中/高 |
| 凭证 | PASSWORD, API_KEY | 正则 | 高 |
| 网络信息 | IP_ADDRESS | 正则 | 中 |
| 车辆信息 | LICENSE_PLATE | 正则 | 中 |
| NLP 实体 | PERSON, ADDRESS, ORGANIZATION | HanLP NER | 低(默认禁用) |
| 扩展 | CUSTOM | 用户自定义 | 视规则而定 |

**[SensitiveEntity](file:///e:/Java/Llm输入输出脱敏与识别/src/main/java/com/hdu/apisensitivities/entity/SensitiveEntity.java)** — 检测出的单条敏感实体，包含 `content`(原文)、`type`(类型)、`start`/`end`(位置)、`confidence`(置信度)。

**DesensitizationRequest/Response** — 脱敏请求/响应模型，请求支持 text/JSON/binary 多种输入，响应包含脱敏后内容+检测到的实体列表。

**LlmRequest/Response** — LLM 代理请求/响应模型，新增 `LlmProvider provider`、`Map<String,Object> parameters`、结构化响应字段。

**LlmProvider** — LLM 提供商枚举：DEEPSEEK, DOUBAO, QWEN, KIMI, HUNYUAN, OPENAI, OLLAMA, CLAUDE。

#### 企业网关模型 `entity/gateway/`

- **GatewayRiskLevel**: NONE / LOW / MEDIUM / HIGH / CRITICAL
- **GatewayDecisionAction**: ALLOW / DESENSITIZE_AND_ALLOW / ROUTE_TO_INTERNAL_MODEL / BLOCK / REQUIRE_APPROVAL / ASYNC_REVIEW
- **GatewayRiskDecision**: 风险决策结果(riskLevel + decisionAction + matchedTypes + policyId)
- **GatewayAuditEvent**: 审计事件全量字段(eventId/timestamp/userId/department/channel/originalContent/processedContent/decisionAction...)
- **GatewayFileTaskInfo**: 异步文件处理任务(taskId/status/progress/fileName/resultUrl)

### 3.4 核心编排 — `DesensitizationManager`

**[DesensitizationManager](file:///e:/Java/Llm输入输出脱敏与识别/src/main/java/com/hdu/apisensitivities/service/DesensitizationManager.java)**

职责：处理脱敏请求的完整流程。是系统最核心的编排器。

处理流程( `process(DesensitizationRequest)` ):
1. **数据解析** → `DataParserManager.parseData()` 将不同格式(TEXT/JSON/XML/PDF/DOCX)统一转为文本
2. **检测范围设置** → `prepareDetectionScopeForCurrentMode()`: 默认排除 PERSON/ADDRESS/ORGANIZATION 三种 NLP 高误报类型，可通过 includeTypes 参数覆盖
3. **敏感检测** → `TextSensitiveDetectionService.detectSensitiveInfo()` 识别敏感实体
4. **重叠消解** → `resolveOverlappingEntities()`: 按优先级(特定度分数 → 跨度 → 置信度)去重，ADDRESS 吞并内部 PERSON/ORG 碎片
5. **策略选择** → `selectStrategy()`: 用户指定 > 数据类型匹配 > 敏感类型匹配 > 默认策略
6. **脱敏执行** → `DesensitizationStrategy.desensitize()` 生成脱敏文本
7. **结果组装** → `DesensitizationResponse` 返回

关键设计：
- 情景感知代码当前被整体注释/禁用，`prepareDetectionScopeForCurrentMode()` 只做默认检测范围设置
- ThreadLocal 会话上下文 `DesensitizeRequestContext` 在 finally 中清理
- `DesensitizationResult` 是内部 POJO，封装原始内容+脱敏内容

### 3.5 LLM 代理 — `LlmProxyService`

**[LlmProxyService](file:///e:/Java/Llm输入输出脱敏与识别/src/main/java/com/hdu/apisensitivities/service/LlmProxyService.java)**

职责：LLM 输入输出的安全代理总入口，在请求发送到 LLM 前做脱敏，响应返回后恢复。

核心流程 `processWithDataSensitiveProtection()`:
1. **构建脱敏请求** → `buildDesensitizationRequestForLlm()`: 按数据类型(TEXT/JSON/XML/IMAGE/AUDIO/PDF/DOC)构建 `DesensitizationRequest`
2. **基础脱敏** → `desensitizationManager.process()`: 正则+NLP 脱敏
3. **语义扫描** → `nlpScanner.extractEntities()`: 调用本地 Ollama 模型识别人名/公司名等语义实体
4. **占位符替换** → `semanticPlaceholderStrategy.desensitize()`: 将语义实体替换为 `[ENTITY_n]`
5. **自检审计** → `agentSelfReflection()`: 调用 Ollama 检查脱敏是否彻底
6. **调用 LLM** → `callLlmApiWithDataType()`: 根据 dataType 调用对应 LlmClient
7. **恢复响应** → `semanticPlaceholderStrategy.restore()`: 将占位符还原为原始语义实体

额外功能：
- `processLlmRequestAsync()`: `@Async` 异步处理
- `batchProcessLlmRequests()`: `parallelStream` 批量处理
- `testAllProviders()`: 测试所有已注册 LLM 提供商的配置有效性

## 8. 关键设计约定

### 8.1 命名规范
- Controller: `*Controller.java`, 路由使用 RESTful 风格
- Service: `*Service.java` (接口) / `*ServiceImpl.java` (实现) 或直接类名
- Entity/DTO: 实体在 `entity/` 包，数据传输对象在 `dto/` 包
- 策略模式: `DesensitizationStrategy` 接口 + 多个 `*Strategy` 实现

### 8.2 并发安全
- `SemanticPlaceholderStrategy.mappingTable`: `ThreadLocal<LinkedHashMap>`
- `DesensitizeRequestContext`: `ThreadLocal` 存储 sessionId
- `EnterpriseGatewayApplicationServiceImpl.fileTasks`: `ConcurrentHashMap`
- `RiskPolicyController.CONFIG`: `static` 内存存储(非线程安全，建议加锁)

### 8.3 检测默认策略
- 17 种敏感类型中，PERSON/ADDRESS/ORGANIZATION 三种 NLP 类型**默认不检测**(高误报)
- 仅国企/政府/严格合规场景通过 `includeTypes` 参数显式开启

### 8.4 双通道 NER
- **规则通道**: HanLP `NlpEntityDetector` → 中文命名实体(PERSON/ADDRESS/ORGANIZATION)
- **语义通道**: Ollama `NlpScanner` → 调用本地模型 `qwen:1.8b` 识别人名/公司名/项目名，用于 LLM 代理场景的语义脱敏
