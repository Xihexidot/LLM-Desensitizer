# 代码大纲

## 1. 项目概览

本项目是一个“LLM 输入输出脱敏与识别”系统，当前由 4 个子系统组成：

- 后端：`Spring Boot 3 + MyBatis + H2/MySQL`
- 前端：`Vue 3 + Vite`
- 浏览器插件：将 DeepSeek 聊天请求重定向到本地安全网关
- 辅助脚本与测试：数据生成、测试脚本、基准测试

核心业务目标：

1. 识别输入内容中的敏感信息
2. 对输入做脱敏后再发送给大模型
3. 接收大模型返回结果后再进行安全处理
4. 支持规则管理、附件解析、多供应商 LLM 代理

## 3. 后端代码大纲

### 3.1 应用入口

- `ApiSensitivitiesApplication`
  - Spring Boot 启动类

### 3.2 配置层 `config/`

- `AsyncConfig`
  - 异步线程池配置
- `CorsConfig`
  - 跨域访问配置
- `LlmConfig`
  - 单个 LLM 提供商配置模型
- `WebConfig`
  - Web 相关配置

### 3.3 接口层 `controller/`

- `DesensitizationController`
  - `/desensitize/text`
  - `/desensitize/structured`
  - `/desensitize/binary`
  - `/desensitize/batch`
  - `/desensitize/health`
  - 作用：统一接收脱敏请求，调用 `DesensitizationManager`

- `LlmProxyController`
  - `/api/llm/proxy`
  - `/api/llm/proxy/structured`
  - `/api/llm/proxy/legacy`
  - `/api/llm/proxy/async`
  - `/api/llm/proxy/batch`
  - `/api/llm/providers`
  - `/api/llm/configs`
  - 作用：LLM 代理统一入口，调用 `LlmProxyService`

- `GatewayController`
  - `/api/v0/chat/completion`
  - 作用：给外部 AI 工具或插件提供兼容 OpenAI/DeepSeek 风格的网关入口

- `SensitiveRuleController`
  - `/rules`
  - 作用：增删改查自定义敏感规则

### 3.4 领域模型 `entity/`

- 请求与响应
  - `DesensitizationRequest`
  - `DesensitizationResponse`
  - `LlmRequest`
  - `LlmResponse`
  - `ApiRequest`
  - `ApiResponse`

- 领域实体
  - `SensitiveEntity`
  - `SensitiveType`
  - `LlmProvider`

这些对象当前同时承担：

1. API 入参/出参
2. 业务中间态
3. 不同模块间传输协议

这是后续重构的重要切分点。

### 3.5 脱敏编排层

- `DesensitizationManager`
  - 核心编排器
  - 负责数据解析、情景感知、敏感检测、策略选择、结果组装

- `Desensitization/`
  - `DesensitizationStrategy`
    - 脱敏策略接口
  - `MaskDesensitizationStrategy`
    - 标识替换/掩码类脱敏
  - `PartialDesensitizationStrategy`
    - 部分保留脱敏
  - `GeneralizationDesensitizationStrategy`
    - 语义泛化
  - `SemanticDesensitizationStrategy`
    - 语义替换
  - `SemanticPlaceholderStrategy`
    - 占位符映射与恢复
  - `DesensitizeRequestContext`
    - 请求上下文
  - `GlobalSessionContextRepository`
    - 全局会话映射仓库

### 3.6 敏感检测层 `service/SensitiveDetection/`

- `SensitiveDetectionService`
  - 统一检测接口，但接口非常宽

- `RegexDetectionService`
  - 当前主实现，混合正则、NLP、自定义规则、结构化检测、二进制检测、批量检测

- 子模块
  - `RegexPatternDetector`
    - 单规则正则检测
  - `NlpDetectionService`
    - NLP 检测
  - `NlpScanner`
    - 面向 LLM 代理的语义扫描
  - `ConfidenceScorer`
    - 置信度打分
  - `EntityMerger`
    - 检测结果合并
  - `StructuredDataDetector`
    - 遍历结构化数据
  - `BinaryDataDetector`
    - 二进制数据转文本后检测
  - `CustomPatternManager`
    - 自定义规则内存管理
  - `SensitiveRuleService`
    - 数据库存储规则 + 刷新内存规则

### 3.7 数据解析层 `service/DataParser/`

- `DataParserService`
  - 解析服务接口
- `DataParserServiceImpl`
  - PDF、DOCX、Excel、JSON、XML 等解析
- `DataParserManager`
  - 对外统一入口，按 `DesensitizationRequest` 决定解析方式

### 3.8 情景感知层 `service/ScenarioPerception/`

- `ScenarioPerceptionService`
  - 情景感知接口
- `KeywordBasedScenarioPerceptionService`
  - 基于关键词计算情景得分
- `LlmBasedScenarioPerceptionService`
  - 调用 LLM 识别业务情景
- `ScenarioAnalysisResult`
  - 情景识别结果

注意：

- `DesensitizationManager` 仍然注入了两种情景感知服务
- 但当前主流程里这段能力被整体注释/禁用，只保留依赖关系

### 3.9 LLM 代理层

- `LlmProxyService`
  - LLM 输入输出安全代理总入口
  - 负责请求构建、脱敏、语义扫描、模型调用、结果恢复

- `LlmConfigService`
  - 管理多供应商配置

- `service/LlmClient/`
  - `LlmClient`
    - 多供应商适配接口
  - `DeepSeekClient`
  - `DoubaoClient`
  - `HunyuanClient`
  - `KimiClient`
  - `OpenAIClient`
  - `QwenClient`
  - `OllamaClient`

### 3.10 数据访问层

- `SensitiveRuleMapper`
  - 自定义规则持久化接口
- `SensitiveRuleMapper.xml`
  - MyBatis SQL 映射
- `schema.sql`

### 3.11 工具层 `utils/`

## 7. 当前最值得优先重构的区域

### 优先级 A

- `LlmProxyService`
  - 业务链路太长，输入构建、脱敏、扫描、调用、恢复、响应组装耦合在一起

- `DesensitizationManager`
  - 同时管理流程编排、策略选择、上下文、黑白名单、情景控制

- `RegexDetectionService`
  - 接口面太宽，承担文本、结构化、二进制、批量、自定义规则等多类职责

- `LlmDesensitization.vue`
  - 前端核心组件过大，状态、动画、上传、导出、请求全部堆在一个文件

### 优先级 B

- `SensitiveDetectionService`
  - 接口方法过多，说明抽象边界不清晰

- `DesensitizationRequest`
  - 文本、结构化、二进制三种输入共用一个对象，容易产生状态混杂

- `LlmConfigService`
  - 多供应商配置目前通过大量字段硬编码维护，扩展性一般

### 优先级 C

- 情景感知模块
  - 当前依赖仍在，但主链路禁用，处于“保留实现但未真正接入”的中间状态

- `App.vue`
  - 应用壳层与页面状态混杂

## 8. 建议的阅读顺序

如果准备正式重构，建议按这个顺序继续深入：

1. `DesensitizationController` -> `DesensitizationManager`
2. `SensitiveDetectionService` -> `RegexDetectionService`
3. `DesensitizationStrategy` 各实现
4. `LlmProxyController` -> `LlmProxyService`
5. `LlmClient` 各供应商实现
6. `DataParserManager` -> `DataParserServiceImpl`
7. `SensitiveRuleService` + `SensitiveRuleMapper`
8. `front_end/src/App.vue` -> `LlmDesensitization.vue`

## 9. 后续重构建议

建议下一阶段把系统拆成 6 个明确子域：

1. API 接口层
2. 脱敏编排层
3. 敏感检测引擎
4. 数据解析引擎
5. LLM 代理层
6. 前端页面与状态层

这样后面重构时就能先“拆职责”，再“换实现”，而不是直接在现有大类里继续叠加逻辑。
