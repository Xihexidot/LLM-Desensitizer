# 当前可演示效果与用户接入方式

## 1. 文档目的

这份文档用于回答两个最实际的问题：

1. 这个项目当前到底已经能演示到什么程度
2. 用户或评委如果要“接到你们项目”，具体应该怎么接，接入后又如何查看效果

这份文档面向：

- 项目组内部沟通
- 比赛答辩演示
- 老师验收说明
- 后续企业版接入说明的过渡版本

## 2. 当前项目的三种接入方式

当前项目已经具备 3 种可以对外演示的接入方式：

1. `前端页面直接使用`
2. `浏览器插件接管网页 AI 请求`
3. `企业版 API 网关接口接入`

三种方式对应的成熟度不同：

- `前端页面`：最成熟，最适合直接演示
- `插件接管`：最贴近真实入口接管场景
- `企业网关 API`：最接近未来企业落地形态

## 3. 方式一：前端页面直接使用

### 3.1 入口位置

前端主入口在：

- [App.vue](file:///e:/Java/Llm输入输出脱敏与识别/front_end/src/App.vue)

页面中的核心功能入口组件在：

- [LlmDesensitization.vue](file:///e:/Java/Llm输入输出脱敏与识别/front_end/src/components/LlmDesensitization.vue)

### 3.2 用户怎么接入

用户打开前端页面后，可以直接在页面中：

- 输入待检测文本
- 发起 LLM 请求
- 查看脱敏和响应结果
- 查看历史记录
- 进入规则管理页

### 3.3 当前能演示的效果

这个入口当前最适合展示下面这条完整闭环：

1. 用户输入一段包含敏感信息的文本
2. 系统识别敏感实体
3. 系统执行脱敏
4. 系统将脱敏后的内容转发给大模型
5. 页面展示模型输出
6. 页面保存会话历史

### 3.4 具体演示示例

可以直接输入下面这段话：

```text
帮我总结一下客户情况：客户张三，手机号13812345678，身份证330102199901011234，地址杭州市西湖区文三路xxx号，请生成一段客服回复建议。
```

预期可展示效果：

- 识别出姓名、手机号、身份证号、地址
- 页面显示脱敏后的输入内容
- 模型返回基于脱敏内容生成的结果
- 会话进入历史记录

### 3.5 用户如何查看结果

用户可以在页面中直接查看：

- 原始输入
- 脱敏后输入
- 模型返回内容
- 历史记录
- 规则页

### 3.6 适合的使用场景

这种方式最适合：

- 比赛演示
- 课堂展示
- 老师验收
- 产品原型说明

## 4. 方式二：浏览器插件接管网页 AI 请求

### 4.1 入口位置

浏览器插件配置文件在：

- [manifest.json](file:///e:/Java/Llm输入输出脱敏与识别/plugin/manifest.json)

插件重定向逻辑在：

- [background.js](file:///e:/Java/Llm输入输出脱敏与识别/plugin/background.js)

当前插件会把 DeepSeek 网页请求重定向到本地网关：

- 原请求目标：`https://chat.deepseek.com/api/v0/chat/completion`
- 重定向目标：`http://127.0.0.1:8080/api/v0/chat/completion`

对应后端网关入口在：

- [GatewayController.java](file:///e:/Java/Llm输入输出脱敏与识别/src/main/java/com/hdu/apisensitivities/controller/GatewayController.java)

### 4.2 用户怎么接入

用户接入步骤如下：

1. 启动本地后端服务
2. 在浏览器扩展管理页中加载 `plugin` 目录
3. 打开 DeepSeek 网页
4. 正常输入问题并发送

### 4.3 当前能演示的效果

这条链路当前可演示的是：

1. 用户仍然在原网页中使用 AI
2. 实际请求先被浏览器插件拦截
3. 请求被导向你们本地网关
4. 本地网关调用现有脱敏与代理逻辑
5. 网关把处理后的结果返回给原网页

也就是说，用户表面上仍然在用原网站，但实际上流量已经先经过你们项目。

### 4.4 具体演示示例

用户在 DeepSeek 网页输入：

```text
请帮我整理这位客户的资料：客户李四，电话13900001111，身份证号330103200001011234，请输出一个客户摘要。
```

当前项目可演示的效果是：

- 请求先进入本地网关
- 网关日志记录原始请求
- 网关复用现有 LLM 脱敏流程
- 返回处理后的响应给网页

### 4.5 用户如何查看结果

这个模式下的“查看结果”分两部分：

- `前台`
  - 用户在 DeepSeek 页面中看到最终回答
- `后台`
  - 项目组成员查看后端日志，确认请求已经经过网关

当前后端日志位置对应逻辑在：

- [GatewayController.java](file:///e:/Java/Llm输入输出脱敏与识别/src/main/java/com/hdu/apisensitivities/controller/GatewayController.java#L33-L68)

### 4.6 这个模式当前的限制

当前插件模式主要是雏形验证，还存在下面这些限制：

- 只针对 DeepSeek 的一个特定接口
- 主要依赖本地重定向，不是企业正式部署形态
- 前台页面不能直接显示“命中了哪些规则”
- 审计查询主要还是依赖日志，不是完整控制台

### 4.7 适合的使用场景

这种方式最适合展示：

- 用户不改使用习惯也能被安全接管
- 网页 AI 工具可以被统一接入安全网关
- 项目具备浏览器入口侧接管能力

## 5. 方式三：企业版 API 网关接口接入

### 5.1 入口位置

企业版网关入口控制器在：

- [EnterpriseGatewayController.java](file:///e:/Java/Llm输入输出脱敏与识别/src/main/java/com/hdu/apisensitivities/controller/EnterpriseGatewayController.java)

当前已经提供的接口骨架有：

- `POST /gateway/v1/chat`
- `POST /gateway/v1/structured`
- `POST /gateway/v1/files/tasks`
- `GET /gateway/v1/files/tasks/{taskId}`
- `GET /gateway/v1/audit/events`

### 5.2 用户怎么接入

这里的“用户”更准确地说是：

- 业务系统
- Postman 调用者
- 企业内部中转服务
- 后续接入的 Agent / RAG 平台

接入方式是直接调用你们的后端接口。

### 5.3 当前能演示的效果

这一版企业接口骨架已经能演示：

1. 统一网关请求结构
2. 统一风险决策结构
3. 统一审计摘要结构
4. 统一文件任务和审计查询入口

其中 `POST /gateway/v1/chat` 已经不是纯空壳，而是会：

1. 接收统一 `GatewayRequest`
2. 读取调用头部上下文
3. 转换为现有 `LlmRequest`
4. 复用现有 [LlmProxyService.java](file:///e:/Java/Llm输入输出脱敏与识别/src/main/java/com/hdu/apisensitivities/service/LlmProxyService.java)
5. 返回统一 `GatewayResponse`

### 5.4 具体演示示例

可以用 Postman 或 curl 调下面这个请求：

```http
POST /gateway/v1/chat
```

请求头示例：

```text

X-Request-Id: req-1001
X-Tenant-Id: tenant-a

X-Trace-Id: trace-1001
X-User-Id: user-001
X-User-Role: staff
X-Department: customer-service
X-Scene-Code: customer_service
X-Environment: prod
```

请求体示例：

```json
{
  "provider": {
    "preferred": "DEEPSEEK",

  "requestContext": {
    "sessionId": "crm-session-001",

  "userContext": {
    "userId": "user-001",

```

### 5.5 用户如何查看结果

调用方当前可以直接从返回结果中查看：

- `success`
- `data`
- `risk`
- `audit`

之后还可以继续调用：

- `GET /gateway/v1/audit/events`

查看当前内存态审计事件结果。

### 5.6 适合的使用场景

这种方式最适合展示：

- 企业系统统一接入 AI 安全网关
- 业务系统如何标准化传递上下文
- 未来企业版的协议和平台接口形态

## 6. 三种接入方式的对比

| 接入方式 | 当前成熟度 | 用户如何查看 | 最适合展示什么 |
| --- | --- | --- | --- |
| 前端页面 | 高 | 页面直接查看 | 敏感识别、脱敏、LLM 闭环 |
| 浏览器插件 | 中 | 原网页结果 + 后端日志 | 不改用户习惯的入口接管 |
| 企业网关 API | 中 | 接口返回 + 审计查询接口 | 企业落地接口形态 |

## 7. 当前建议的标准演示脚本

如果是正式演示，建议不要把三种入口混在一起乱讲，而是按下面顺序演示。

### 7.1 第一段：先演示页面版

步骤：

1. 打开前端页面
2. 输入一段带手机号、身份证、地址的信息
3. 展示识别与脱敏结果
4. 展示模型响应
5. 展示历史记录

这一段的目的：

- 先让评委快速看懂项目是做什么的

### 7.2 第二段：再演示插件接管版

步骤：

1. 打开浏览器扩展页，展示插件已加载
2. 打开 DeepSeek 网页
3. 输入一段带敏感信息的问题
4. 展示网页仍能正常回答
5. 展示后端日志，说明流量已经先经过你们网关

这一段的目的：

- 证明项目不是只能做页面 demo，而是能接管真实入口

### 7.3 第三段：最后演示企业网关 API

步骤：

1. 用 Postman 调 `POST /gateway/v1/chat`
2. 展示返回里的 `risk` 和 `audit`
3. 再调 `GET /gateway/v1/audit/events`
4. 展示企业版接口骨架已经存在

这一段的目的：

- 证明项目未来可以演进成企业 AI 安全网关

## 8. 当前能讲的“已实现能力”与“尚未完全实现能力”

### 8.1 当前已实现能力

- 页面版敏感识别与脱敏演示
- LLM 请求代理
- 浏览器插件重定向 DeepSeek 请求
- 本地网关接管 DeepSeek 单接口
- 企业版统一网关对象骨架
- 企业版风险决策和审计摘要骨架
- 文件任务与审计查询接口骨架

### 8.2 当前尚未完全实现能力

- 完整企业审计后台页面
- 持久化审计数据库
- 真正的策略中心和策略发布能力
- 企业级风险决策引擎
- 真正异步文件治理流水线
- 插件模式下的前台显式风险提示
- 完整规则命中明细查询

## 9. 对外讲解时的推荐表述

如果对老师、评委或企业老师介绍当前状态，推荐这样讲：

- `当前项目已经实现了从演示页面到浏览器入口接管，再到企业网关接口骨架的三层能力。`
- `其中页面版可以完整展示识别、脱敏和代理调用闭环；插件版可以证明原网页 AI 请求可被安全接管；企业版接口骨架则说明项目具备继续演进为企业 AI 安全网关的基础。`

## 10. 结论

当前项目最适合的对外展示方式不是只展示一个网页，而是按下面的逻辑来讲：

1. `先看页面`
2. `再看插件接管`
3. `最后看企业网关接口`

这样既能证明“现在能演示”，也能证明“未来能落地”。
