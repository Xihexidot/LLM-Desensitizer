# 当前可演示效果与用户接入方式

## 1. 文档目的

这份文档用于回答两个最实际的问题：

1. 这个项目当前到底已经能演示到什么程度
2. 用户或评委如果要“接到你们项目”，具体应该怎么接，接入后又如何查看效果

这份文档面向：

- 项目组内部沟通
- 比赛答辩演示
- 老师验收说明
- 后续企业版接入说明的过渡版本

## 2. 当前项目的四种接入方式

当前项目已经具备 4 种可以对外演示的接入方式：

1. `前端 Dashboard（管理员控制台）`
2. `浏览器插件接管网页 AI 请求`
3. `企业版 API 网关接口接入`
4. `管理员审计与策略管理`

四种方式对应的成熟度不同：

- `前端 Dashboard`：最成熟，首页即为仪表盘，适合直接演示
- `插件接管`：最贴近真实入口接管场景，现已接入完整审计管道
- `企业网关 API`：最接近未来企业落地形态
- `管理员审计`：贯穿全链路的审计查询与策略管理闭环

## 4. 方式二：浏览器插件接管网页 AI 请求（含审计管道）

### 4.1 入口位置

浏览器插件配置文件在：

- [manifest.json](file:///e:/Java/Llm输入输出脱敏与识别/plugin/manifest.json)

插件核心文件：

- [background.js](file:///e:/Java/Llm输入输出脱敏与识别/plugin/background.js) — Service Worker，接收 content 消息，转发到后端审计管道
- [content.js](file:///e:/Java/Llm输入输出脱敏与识别/plugin/content.js) — 页面注入脚本，截获发送动作 + 检测目标平台
- [popup.js](file:///e:/Java/Llm输入输出脱敏与识别/plugin/popup.js) — 弹窗展示检测结果和用户选项

当前插件在用户点击发送前截获输入内容，发送到后端审计管道进行检查，弹窗展示结果，用户选择后写回审计记录。

**核心改进（v2.0）**：

- 检查目标已从 `POST /desensitize/text` 改为 `POST /plugin/audit-check`（PluginAuditController 审计管道）
- 每条检测写入 `gateway_audit_event` 表，含 `userId` / `department` / `targetProvider` / `originalContent` / `processedContent`
- 用户选择（发送脱敏版 / 发送原文 / 取消）通过 `POST /plugin/confirm-action` 回写审计表
- 插件端自动检测当前网页域名，映射为 LLM 平台名（如 `DeepSeek` / `ChatGPT` / `Kimi` / `通义千问` / `豆包` 等），作为 `targetProvider` 记录
- 用户选择后右下角出现 2.5s toast 确认操作已记录

当前插件覆盖的 AI 网站（含自动平台识别）：

- `chat.deepseek.com` → DeepSeek
- `chatgpt.com` / `openai.com` → ChatGPT
- `gemini.google.com` → Gemini
- `kimi.moonshot.cn` → Kimi
- `www.doubao.com` → 豆包
- `tongyi.aliyun.com` / qwen 相关 → 通义千问
- `yiyan.baidu.com` → 文心一言
- `claude.ai` → Claude
- `hunyuan.tencent.com` → 混元
- `www.perplexity.ai` → Perplexity

对应后端检查入口：

- [PluginAuditController.java](file:///e:/Java/Llm输入输出脱敏与识别/src/main/java/com/hdu/apisensitivities/controller/PluginAuditController.java)

### 4.2 用户怎么接入

用户接入步骤如下：

1. 启动本地后端服务
2. 在浏览器扩展管理页中加载 `plugin` 目录
3. 打开任意支持的 AI 网站（如 DeepSeek）
4. 正常输入问题并发送

### 4.3 当前能演示的效果（完整审计闭环）

1. 用户在支持的 AI 网站输入包含敏感信息的文本
2. 点击发送时，插件截获输入内容并发送到后端 `POST /plugin/audit-check`
3. 后端检测并写入审计表（含完整原文、脱敏后内容、用户身份、目标平台）
4. 弹窗展示命中的敏感类型和脱敏后内容
5. 用户选择"发送脱敏版"/"发送原文"/"取消"
6. 用户操作通过 `POST /plugin/confirm-action` 回写审计表
7. 右下角 toast 确认操作已记录
8. **管理员在 Dashboard/AuditList 即时可见这条审计记录**

### 4.4 具体演示示例

用户在 DeepSeek 网页输入：

```text
请帮我整理这位客户的资料：客户李四，电话13900001111，身份证号330103200001011234，请输出一个客户摘要。
```

完整演示流程：

1. 点击发送 → 插件拦截，发送到 `POST /plugin/audit-check`
2. 弹窗显示命中类型：PERSON_NAME、PHONE_NUMBER、ID_CARD
3. 弹窗展示脱敏后文本：[NAME_1] [PHONE_1] [ID_CARD_1]
4. 用户选"发送脱敏版" → 脱敏内容填入输入框并发送；操作写入审计表
5. 右下角 toast："[AI安全助手] 已选择发送脱敏内容"
6. **管理员刷新 Dashboard → 审计列表中出现这条记录，可展开查看原始/脱敏原文**

### 4.5 用户如何查看结果

- `插件弹窗`：显示命中的敏感类型和脱敏后预览，提供三个选项
- `管理控制台`：管理员在 Dashboard 或 AuditList 即时可见每条审计记录
- `审计详情`：点击"详情"可查看完整事件信息（基本信息 / 风险决策 / 原始 vs 脱敏内容左右对比）

### 4.6 这个模式当前的限制

- 依赖本地后端服务运行
- 弹窗展示的是输入侧检测结果，不覆盖 LLM 输出侧审查
- 未实现请求重定向（即仍是"发送前检查"而非透明代理）

### 4.7 适合的使用场景

- 员工不改使用习惯也能被安全监控
- 网页 AI 工具可被统一接入安全审计
- 插件→后端→Dashboard 完整闭环演示

## 5. 方式三：企业版 API 网关接口接入

### 5.1 入口位置

企业版网关入口控制器在：

- [EnterpriseGatewayController.java](file:///e:/Java/Llm输入输出脱敏与识别/src/main/java/com/hdu/apisensitivities/controller/EnterpriseGatewayController.java)

当前已经提供的接口：

**调用接口**：

- `POST /gateway/v1/chat` — 文本聊天（含脱敏→LLM→输出审查完整链路，写入审计）
- `POST /gateway/v1/structured` — 结构化输入
- `POST /gateway/v1/files/tasks` — 文件任务创建
- `GET /gateway/v1/files/tasks/{taskId}` — 文件任务查询

**审计与统计接口**：

- `GET /gateway/v1/audit/events` — 查询审计事件列表（支持 `userId` / `appId` / `decisionAction` 筛选）
- `GET /gateway/v1/audit/events/{eventId}` — 查询单条审计事件详情
- `GET /gateway/v1/audit/stats` — 审计统计（今日总数 / 按渠道 / 按风险等级 / 按决策动作 / 按目标LLM供应商 / 按用户操作）

**插件审计管道接口**（PluginAuditController）：

- `POST /plugin/audit-check` — 插件发送前检查（检测 + 写入审计表 + 返回脱敏结果和 auditEventId）
- `POST /plugin/confirm-action` — 插件用户操作确认（回写 userAction 到审计表）

### 5.2 用户怎么接入

这里的“用户”更准确地说是：

- 业务系统
- Postman 调用者
- 企业内部中转服务
- 后续接入的 Agent / RAG 平台

接入方式是直接调用你们的后端接口。

### 5.3 当前能演示的效果

这一版企业接口骨架已经能演示：

1. 统一网关请求结构
2. 统一风险决策结构
3. 统一审计摘要结构
4. 统一文件任务和审计查询入口

其中 `POST /gateway/v1/chat` 已经不是纯空壳，而是会：

1. 接收统一 `GatewayRequest`
2. 读取调用头部上下文
3. 转换为现有 `LlmRequest`
4. 复用现有 [LlmProxyService.java](file:///e:/Java/Llm输入输出脱敏与识别/src/main/java/com/hdu/apisensitivities/service/LlmProxyService.java)
5. 返回统一 `GatewayResponse`

1. 管理员打开前端 → 首页即仪表盘，看到今日拦截总数 / 插件检测次数 / API 调用次数 / 高风险次数

## 9. 当前能讲的“已实现能力”与“尚未完全实现能力”

### 9.1 当前已实现能力

- **Dashboard 仪表盘**：4 指标卡 + 饼图 + 最近审计事件表格（可展开查看原文/脱敏对比），10s 自动刷新
- **审计日志**：DB 持久化审计事件列表（支持用户筛选、展开原文、跳转详情）
- **审计详情**：独立详情页（基本信息 + 风险决策 + 原始/脱敏内容左右对比）
- **浏览器插件**：多网站输入检测 + 审计管道（写入 audit 表 + 用户操作回写 + 目标平台自动识别）
- **插件→Dashboard 闭环**：员工在 DeepSeek 输入 → 弹窗 → 管理员即时可见审计记录
- **风险策略配置**：可编辑场景策略矩阵（增删改 + Toggle 启用/禁用）
- **词典管理**：4 种词典类型切换 + 词条增删 + 热重载
- **调用监控**：按 targetProvider 统计员工访问各外部 LLM 平台的次数
- **企业网关 API**：`POST /gateway/v1/chat`（含脱敏→LLM→输出审查完整链路 + 写入审计）
- **审计统计接口**：`GET /gateway/v1/audit/stats`（按渠道/风险/决策/目标LLM分组）
- **DB 持久化**：`gateway_audit_event` 表（含 original_content / processed_content / user_action / target_provider 等 20+ 字段）
- **脱敏测试工具**：手动测试脱敏和 LLM 代理（降级为侧栏工具页）
