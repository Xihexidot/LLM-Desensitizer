## 2. 信息安全竞赛评审标准

### 2.1 官方评审维度

根据全国大学生信息安全竞赛官网公布的规则，初赛评审维度为：

1. **作品创新性** — 技术思路是否新颖，是否有独创贡献
2. **技术先进性** — 采用的技术方案是否处于前沿水平
3. **应用前景** — 是否解决真实安全痛点，是否有落地价值
4. **设计完整性** — 功能是否完整闭环，架构是否合理
5. **文档规范性** — 报告是否专业、结构是否清晰

决赛为 30 分钟现场演示+答辩，**会现场检查源代码**。评委将关注代码是否由学生独立完成。

### 2.2 参考评分标准（高分导向）

| 维度 | 分值 | 关键得分点 |
|------|------|-----------|
| 创新性 | 30 | 原创方案、新技术新方法、架构独特性 |
| 实用性 | 30 | 功能完整闭环、系统稳定可演示、用户体验好 |
| 工程化 | 20 | 代码质量、架构设计、AI 工具使用规范化 |
| 文档与演示 | 20 | 报告专业度、现场演示效果 |

### 2.3 比赛关键时间节点

- 6 月初：线上提交作品（报名截止 + 作品提交截止）
- 6 月中旬-7 月上旬：线上初评
- 7 月下旬：线下决赛会评

**结论：我们有一个月时间完成作品打磨，时间紧迫但可行。**

### 3.2 竞品弱点总结

| 弱点 | 说明 |
|------|------|
| **重 SDK / 轻入口接管** | 绝大多数竞品提供 SDK 或 API 代理，几乎没有一个提供浏览器插件来做"用户无感"的入口层接管 |
| **重云端 / 轻本地方案** | 商用品都面向企业集群部署，没有一个同时提供本地一键启动 + 前端可视化 + 插件侧覆盖的完整方案 |
| **重检测 / 轻场景联动** | 大部分只做 PII 检测 → 脱敏，不关心"这是客服场景还是研发场景"，不做情景感知策略调整 |
| **重技术 / 轻合规闭环** | 开源品大多只输出检测结果，没有形成"输入→检测→脱敏→决策→审计→报表"的合规闭环 |
| **无国内学生竞赛作品** | 当前没有已知的 CISCN 作品赛项目聚焦"LLM API 安全网关+浏览器插件"这一完整链路 |

### 3.3 最需关注的直接竞品

1. **AegisGate**（2026 年活跃开源）— 架构最像我们（代理+插件），但走 CLI 路线而非 Chrome 插件
2. **Secure-Sense**（学生 Hackathon 作品）— 技术栈相似（Chrome 插件+Flask+OLLAMA），但只有检测没有网关转发
3. **FiltroBox12**（学生项目）— UI 精美，但只是一个 React 前端中间件，无网关能力

## 4. 我们的差异化定位

### 4.1 一句定位

> **"浏览器安全入口 + 企业统一网关"双模架构的 LLM API 敏感数据治理系统**

### 4.2 六大差异化优势

| 差异化点 | 具体内容 |
|----------|----------|
| **双入口架构** | 浏览器插件（用户无感）+ 企业网关 API（业务系统接入双通道），这是竞品中没有的 |
| **完整治理闭环** | 输入检测 → 多策略脱敏（掩码/部分保留/泛化/语义替换）→ LLM 代理转发（8 供应商）→ 输出审查 → 审计留痕 |
| **情景感知策略** | 根据业务场景（客服/金融/医疗/研发）动态调整敏感类型范围和严格度，不是一刀切脱敏 |
| **企业级网关协议** | 自主设计了统一网关请求/响应协议，支持风险决策（放行/脱敏/内部路由/阻断/审批）和审计摘要 |
| **多格式数据解析** | 支持文本、JSON/XML、PDF、DOCX、Excel、二进制附件的统一检测和脱敏 |
| **一键演示部署** | 后端 Spring Boot + 前端 Vue 3 + 插件 Chrome Extension 三端一体，本地即可完整演示 |

### 4.3 竞品对比一句话总结

> 竞品要么是"云端集群级商业产品"（企业负担重），要么是"单一检测 SDK"（没有完整链路）。我们恰好填补了"可一键演示又具备企业级架构雏形"的中间空白，特别适合竞赛展示。

## 5. 路线可行性分析

### 5.1 当前能力盘点

| 模块 | 完成度 | 说明 |
|------|--------|------|
| 文本敏感检测（正则+NLP） | 90% | 多正则模式 + HanLP NER，置信度评分 |
| 结构化/附件解析 | 85% | JSON/XML/PDF/DOCX/Excel 已支持 |
| 脱敏策略（6种） | 85% | 掩码/部分保留/泛化/语义/数据替换/占位符 |
| LLM 代理（8 供应商） | 90% | DeepSeek/OpenAI/Qwen/豆包/Kimi/混元/Ollama |
| 浏览器插件 | 70% | 发送前检测模式，需升级为完整网关链路 |
| 前端可视化 | 85% | 10 个组件，交互功能完整 |
| 企业网关骨架 | 60% | Controller 完整，Service 骨架待填充 |
| 情景感知 | 40% | 依赖注入就绪，主流程未启用 |
| 审计与指标 | 20% | 只有日志，无审计查询/统计面板 |
| 规则管理系统 | 85% | CRUD + 词典管理，前端+后端完整 |

### 5.2 核心风险与应对

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| 插件未升级为网关模式 | 中 | 高 | 降级方案：保持"发送前检查"模式，同时补齐企业网关 HTTP API 入口做并行演示 |
| 企业网关链路未打通 | 中 | 高 | 优先让 GatewayController 替换 DesensitizationController 做端到端串联，哪怕先走同步 stub |
| 审计面板来不及做 | 高 | 中 | 用 JSON 日志 + DashboardStats.vue 做基础可视化替代 |
| 情景感知主流程未恢复 | 高 | 中 | 用关键词模式恢复一条低成本链路即可满足演示 |
| 无真实场景数据 | 低 | 中 | 已有 30k 样本数据 + 脚本生成工具，足够 |

### 5.3 可行性结论

**路线可行，但需要聚焦。** 核心策略：
- **保底线**：前端 + 后端脱敏检测 + LLM 代理 + 浏览器插件 = 完整演示闭环（已有 85%）
- **提亮点**：补齐企业网关链路 + 决策/审计骨架 + 情景感知恢复 = 差异化竞争点
- **去水分**：暂停非核心重构，集中精力串联合规闭环

## 7. 演示场景设计（答辩核心）

### 场景一：员工误传客户数据（浏览器插件 + 网关审查）

1. 评委扮演"员工"，在 DeepSeek 网页输入含敏感信息的客服问题
2. 插件弹出安全检测弹窗，展示命中类型（姓名、手机号、身份证、地址）
3. 选择"发送脱敏版"
4. 后端网关接收 → 检测 → 脱敏 → 转发 LLM → 输出审查 → 返回结果
5. Dashboard 展示本次调用的审计记录：谁、什么场景、命中什么规则、做了什么决策

**展示要点**：用户无感、入口侧接管、全链路可见

### 场景二：业务系统 API 接入（企业网关 HTTP 调用）

1. 使用 Postman / curl 模拟 CRM 系统调用 `POST /gateway/v1/chat`
2. 请求体包含结构化客户数据（JSON 中有手机号、身份证等）
3. 网关自动分级检测 → 风险决策"脱敏后放行" → 路由到 DeepSeek
4. 响应中包含 `risk` 和 `audit` 字段，展示决策可解释性

**展示要点**：企业级网关协议、标准 API 接入、策略可解释

### 场景三：附件文件检测（数据解析 + 脱敏）

1. 上传包含敏感信息的 Excel/PDF 文件
2. 系统自动解析文件内容 → 提取文本 → 检测 → 脱敏 → 展示结果
3. 对比脱敏前后的文档片段

**展示要点**：非纯文本场景覆盖、格式解析能力

## 8. 作品报告结构建议

按 CISCN 惯例，报告应包含以下章节：

1. **作品背景与意义**（1500字）
   - LLM 应用爆发 + 数据泄露风险现状
   - 竞品不足与我们的切入点
   - 选题价值

2. **系统方案**（3000字）
   - 双模架构设计（插件 + 网关）
   - 关键模块：检测引擎、脱敏策略、情景感知、LLM 适配、审计
   - 核心算法原理（正则 + NLP 混合检测、置信度评分）

3. **系统实现**（2500字）
   - 技术栈与开发环境
   - 各模块实现细节
   - 关键代码逻辑（可截图）

4. **测试与评估**（2000字）
   - 检测准确率测试（正则 + NLP 各自指标）
   - 脱敏效果对比（不同策略的覆盖率/可读性）
   - 性能基准（吞吐量、延迟）
   - 支持的 LLM 供应商兼容性

5. **创新点总结**（1000字）
   - 浏览器插件 + 企业网关双模入口
   - 情景感知驱动的策略自适应
   - 多策略脱敏引擎
   - 合规闭环（检测→脱敏→决策→审计）

6. **应用前景**（1000字）
   - 企业落地路径
   - 可适配行业场景
   - 未来扩展方向

## 9. 答辩策略要点

1. **开场 3 分钟定调**：直接演示场景一，用真实网页 + 插件弹窗抓住注意力
2. **架构图必讲**：双模架构图是最重要的 PPT 页，讲清楚数据流向
3. **竞品对比表**：用一张表展示我们的差异化（竞品做不到的我们做到了）
4. **现场代码展示**：评委要求检查源代码时要能快速定位关键逻辑
5. **数据说话**：准确率、延迟、支持供应商数量都能量化就量化
6. **不要过度承诺**：坦诚当前版本的限制，但要说明演进路线
